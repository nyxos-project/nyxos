# NyxOS audit, November 2026: Settings, installs, integrations

Checked on Nocturne, a real laptop installed from the ISO and on known-good/28 (NyxOS `1c584ec`, nyx-packages `0202bd6`), against the app repos on Hades (Omarchy with the Nyx apps). Goal: NyxOS has everything Hades has, plus its own extras.

## 1. Root cause: the apps call Omarchy's scripts

The Nyx apps call **210 distinct `omarchy-*` commands**. NyxOS ships none of them: `omarchy-shell` is mentioned in its modules but not installed. Where a command is missing, the feature hides itself, shows "Needs omarchy-…", or does nothing. 30 of the 210 aren't on Hades either: they are stale names or theme ids, listed at the end.

| App | Omarchy commands |
|---|---|
| nyx-settings | 165 |
| nyx-control-center | 20 |
| nyx-notification-center | 12 |
| nyx-design | 7 |
| nyx-biometrics | 7 |
| nyx-assistant | 6 |
| nyx-dock | 5 |
| nyx-core, nyx-bar | 4 each |
| glimpse, shell, photos, notes, git, browser, agents, activity | 1–2 each |

## 2. Settings pages hidden on NyxOS

Settings has 52 pages. Each page states what it needs (`nyx-settings/apps/settings/src/sections/mod.rs`), and these four don't show on Nocturne:

| Page | Needs | Why it's missing | Fix |
|---|---|---|---|
| **Sound** | `daemon:audio`, meaning `pactl` | PipeWire runs, but NyxOS doesn't install `pactl` (`nyx-core/crates/nyx-capability/src/providers.rs`, `Audio`) | Ship `pactl` (pulseaudio's tools only) or check `wpctl` |
| **Sign-in & Security** | `nyx-authctl` | nyx-biometrics isn't on by default and isn't in the catalog | Turn it on by default; NixOS module `nyx-packages/modules/nixos/biometrics.nix` exists |
| **Printers** | `lpstat` | Printing is off by default, so the page hides | Show the page with "Turn on printing" |
| Bar & Notifications | `omarchy-shell` | Omarchy-only | Correctly hidden; NyxOS has the Nyx Bar page |

Connected Devices shows, with a Start button, because `fluxd` only runs once a phone is paired. That's fine. Clipboard features need `nyx-clipboardd`, but Nyx Clipboard is store-only and system-wide, so it isn't there by default.

## 3. Installs: every catalog item against stable

All 118 catalog items (132 packages) were evaluated at NyxOS `1c584ec`, and each output was checked against cache.nixos.org and nyxos.cachix.org.

- **Nyx Assistant:** evaluating it does a full `git clone` of `github.com/design-nexus/nyx-ai`, because of `allowBuiltinFetchGit = true` in `nyx-packages/pkgs/nyx-assistant.nix`. On Nocturne this timed out after 300 s, and the evaluation failed. This is very likely what broke the Welcome batch that included the Assistant. **Fix:** `cargoLock.outputHashes` instead of the built-in fetch.
- **Builds from source:** six packages aren't in either cache.
  - `code-cursor`, `discord`, `vivaldi` and `vscode` are unfree and download the vendor's binary, which is fast.
  - **`lutris` and `nh` really compile.** Find out why NyxOS's copies differ from nixpkgs' (an overlay?), or have CI push them to nyxos.cachix.org.
- **Every other item, including every Nyx app, evaluates and comes from a cache.** One item, `kdePackages.kdenlive`, needs a nested-name check in the sweep; this is a script limitation, not a known failure.
- **Nyx apps you can't install at all:**
  - `nyx-messages` and `nyx-tv` have no package.
  - `nyx-pulse`, `nyx-desktop-widgets` and `nyx-biometrics` have packages or modules, but aren't in the catalog.

## 4. CLI

- `nyx search TERM` prints nix's raw `evaluating 'legacyPackages…'` lines under "In the package collection".
- `nyx list` prints raw `nix profile list` output: store paths and lock URLs.

## 5. Other things seen on Nocturne

- `nyx update` showed "up to date" on systems installed from the USB stick. Fixed in nyx-system `b5a1ffa` and pinned in nyxos `fdd721c`, which has passed CI and is waiting to be promoted.
- hypridle (SIGABRT, 5 times a boot) and PipeWire (SIGSEGV) crash under UID 995, the login screen's session, not yours.
- Harmless warnings in the journal:
  - duplicate D-Bus service files: user and system profiles both ship gnome-keyring, gvfs and portals;
  - Nyx Files' `FileManager1` service file isn't named after its D-Bus name.

## Fix order

1. Small fixes:
   - `pactl`;
   - nyx-biometrics on;
   - Printers page offers to turn printing on;
   - Assistant's eval-time clone;
   - the catalog gaps (`nyx-pulse`, `nyx-desktop-widgets`, `nyx-biometrics`, VPN apps);
   - the `lutris`/`nh` cache misses;
   - CLI output.
2. A `nyx-core/crates/nyx-platform` crate and a `nyx platform …` command: one function per job above. On NyxOS it does the work itself; on Omarchy it calls the `omarchy-*` script. Apps then switch over in this order:
   1. Wi-Fi and VPN (Settings › Network, Control Center);
   2. Display and Brightness;
   3. Input, Power and Notifications;
   4. the rest of Settings;
   5. Control Center, Notification Center, Dock, Bar, Assistant and the rest.
3. Arch-only installers and update flows map to `nyx install` and `nyx update` on NyxOS, or stay hidden there with a reason.
