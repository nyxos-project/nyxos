### NYX-APP-MUSIC-002: Icon-only controls named only through tooltips

- **Component:** nyx-music `apps/music/src/playerbar.rs`, `widgets.rs`
- **Category:** accessibility
- **Severity:** P3
- **Status of feature:** implemented, not verified
- **Description:** Icon-only buttons get a tooltip but almost never an explicit accessible label (2 `update_property` calls in the app). GTK 4 does derive a name from the tooltip in most cases, so this is likely acceptable, but toggles whose tooltip changes with state need checking.
- **Expected:** Every icon-only control exposes a stable accessible name and state (A11Y area standard).
- **Actual:** `playerbar.rs:244-248` repeat `ToggleButton` built with an icon and no label at construction.
- **Reproduce / verify:** static; confirm at runtime with Orca or `accerciser` on the player bar.
- **Evidence:** audit heuristic (static grep): 14 button constructions, 7 without a tooltip/label within 8 lines (most are rows with text children).
- **Affected versions:** `c1d13d2229`
- **User impact:** Screen-reader users may hear unnamed or stale toggle names.
- **Recommended correction:** Use `update_property(&[Property::Label(..)])` for icon-only toggles and update it with state.
- **Effort:** S
- **Dependencies:** NYX-A11Y findings
- **Verification criteria:** Accessibility inspector shows names for all player-bar controls.
