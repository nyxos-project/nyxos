# NyxOS desktop defaults: the reference desktop, captured and translated

Handoff 09, stages A and C. Captured 2026-11-08 from Ken's Omarchy laptop (Omarchy
`omarchy-settings 4.5.0rc2`, Hyprland 0.56 with the Lua config, ASUS ROG G16). Every value
below was read from the file named, and Hyprland's were confirmed with
`hyprctl getoption -j`. `scripts/capture-desktop-settings` reproduces the capture; nothing in
this document was guessed.

The reference is the **effective** desktop: Omarchy's defaults plus everything layered on
them. Stock Omarchy values are listed only where the effective value comes from them.

## Where the reference values come from

Omarchy's defaults are installed system-wide, not in `~/.local/share/omarchy`:

| Label | Path |
| --- | --- |
| stock | `/usr/share/omarchy/default/hypr/*.lua` (`looknfeel`, `input`, `envs`, `windows`, `bindings/*`) |
| stock shell | `/usr/share/omarchy/config/omarchy/shell.json` |
| state | `~/.local/state/omarchy/` (current theme, toggles, workspace layouts) |
| user | `~/.config/hypr/{hyprland,bindings,looknfeel,monitors,autostart}.lua` |
| asus | `~/.config/hypr/asus-g16.lua`, written by the `asus.rog-g16` Omarchy plugin |
| settings | `~/.config/hypr/settings.lua`, generated by Nyx Settings from `~/.config/nyx-settings/state.json` |
| nyx | `~/.config/nyx/*.toml`, `~/.config/nyx-settings/*.toml` |
| gsettings | `org.gnome.desktop.interface` (dconf) |

Hyprland loads them in this order, later ones winning: stock → theme override
(`state/current/theme/hyprland.lua`) → user files → asus → toggles
(`state/toggles/hypr/*.lua`) → inline blocks and `nyx*.lua` rule files → settings.

## Destinations

Every translated setting lands in one of these. Override and reset behave the same for all
settings with the same destination.

| Destination | Owner | Shipped default | User override | Reset |
| --- | --- | --- | --- | --- |
| `hyprland` | Hyprland, through NyxOS's generated `hyprland.lua` | `defaults/hyprland.toml`, rendered by `modules/home/hyprland.nix`; also `/etc/nyxos/defaults/hyprland.toml` so Settings can show it | Nyx Settings' `state.json` → `~/.config/hypr/settings.lua`, loaded last. Hyprland refuses a gesture an earlier one shadows, so Settings unsets each shipped gesture (read from the installed copy) before setting its own on the same fingers and direction | The key leaves `state.json`; Hyprland reloads and the NyxOS value shows through |
| `binds` | Hyprland, through `hyprland.nix` (one block per enabled app) | `modules/home/hyprland.nix` | Settings' Keyboard Shortcuts (`state.binds`/`unbinds`) | The bind leaves `state.json` |
| `dock` | Nyx Dock | `defaults/dock.toml` → `/etc/nyxos/defaults/dock.toml` | `~/.config/nyx/dock.toml`, only the keys the user changed | The key leaves the user file (`nyx-config` reset) |
| `control-center` | Nyx Control Center | `defaults/control-center.toml` | `~/.config/nyx/control-center.toml` | Same |
| `notifications` | `nyx-notifyd` | `defaults/notifications.toml` | The settings row in `notifications.db`, only changed fields | Field removed from the row |
| `idle` | NyxOS idle (`nyx-system config idle`) | `nyxos.idle.*` → `/etc/nyxos/defaults/idle.toml` | `~/.config/nyx/idle.toml` | `nyx-config` reset |
| `appearance` | Theme Engine (`nyx-theme-core`, `nyx-themed`) | `nyxos.theme.system` → `/etc/nyxos/defaults/appearance.toml` | `~/.config/nyx/theme.toml` (`theme`) | The user key goes; the system theme follows the NyxOS default |
| `desktop` | `modules/nixos/desktop.nix`: fonts, icons, cursor | the system dconf database and fontconfig | the user's own dconf (gsettings) | `gsettings reset` |

## Inventory and translation matrix

Classification: **N** native NyxOS equivalent, **I** requires NyxOS implementation (done in
this handoff unless marked open), **K** supported under a different key, **H**
hardware-specific (excluded from global defaults), **A** application-specific (excluded),
**O** obsolete or unsupported, **U** needs Ken's decision (adopted for now, see the last
section).

"Validated" means the shipped value equals the reference: for Hyprland options,
`scripts/capture-desktop-settings --compare defaults/hyprland.toml` checks every shipped key
against the live value on the reference machine; the rest were compared by hand with the
files named. "VM" means it still has to be checked on the NyxOS VM.
